# Plan: Fix Bot Not Forwarding Messages

## Root Cause Analysis

The Playwright-based bot (`playwright_continuous_bot.py`) fails to forward any tweets because:

1. **No cookies file exists** - `data/twikit_cookies.json` is missing (only `.gitkeep` in `data/`). The bot raises an exception at `init_browser()` line 338.
2. **X/Twitter anti-bot detection** - Even with valid cookies, headless Chromium is detected by X's bot protection. No stealth evasion is used.
3. **Fragile DOM scraping** - The JS selectors (`article[data-testid="tweet"]`, `a[href*="/status/"]`) break when X changes its frontend.
4. **The `main.py` Nitter approach** is also broken - Nitter instances are largely dead.

## Recommended Solution: Replace Playwright with twikit

**twikit** is already in `requirements.txt` but is **not used** in `playwright_continuous_bot.py`. It's purpose-built for this exact use case:

- **No browser needed** - Uses `httpx/aiohttp` to call Twitter's internal GraphQL API directly
- **Cookie-based auth** - Same cookie format already expected by the bot
- **4.4k GitHub stars**, actively maintained (v2.3.1)
- **Lighter** - No Chromium process (~0 MB vs ~200 MB for headless browser)
- **More reliable** - Proper API responses, not fragile DOM scraping

## Implementation Steps

### Step 1: Refactor `playwright_continuous_bot.py` to use twikit

Replace the Playwright browser management section with twikit client:

- Remove: `init_browser()`, `check_auth_valid()`, `fetch_tweets_page()`, `close_browser()`, and all Playwright imports
- Add: twikit `Client` initialization with cookie-based login
- Add: `fetch_tweets_twikit()` function that calls `client.get_user_tweets(user_id, 'Tweets')`
- Convert twikit tweet objects to the existing dict format (`id`, `text`, `timestamp`, `url`, `author`)

Key twikit API:
```python
from twikit import Client
client = Client('en-US')
await client.login(
    auth_info_1=TWITTER_USERNAME,
    auth_info_2=TWITTER_EMAIL,
    password=TWITTER_PASSWORD,
    cookies_file=str(COOKIES_FILE)
)
# Or just load from cookies:
await client.set_cookies(cookies_file=str(COOKIES_FILE))

# Get user ID first
user = await client.user(username=TWITTER_USERNAME)
# Fetch tweets
tweets = await client.get_user_tweets(user.id, 'Tweets')
```

### Step 2: Add new env vars for twikit auth

Add to `.env`:
- `TWITTER_EMAIL` - Email for login (optional if using cookies only)
- `TWITTER_PASSWORD` - Password for login (optional if using cookies only)

Keep `TWITTER_USERNAME` (already exists).

- `tweet.created_at` - Datetime
- `tweet.user.name` / `tweet.user.screen_name` - Author info
- `tweet.favorite_count`, `tweet.retweet_count` - Metrics

Convert these to the existing dict format so the sentiment analysis and Discord sending logic remains unchanged.

## Auth Strategy

User has Twitter credentials (email + password). twikit supports:
1. **First run**: Login with credentials → cookies saved to `data/twikit_cookies.json`
2. **Subsequent runs**: Load cookies from file (faster, avoids repeated logins)
3. **Cookie expiry**: Re-login with credentials automatically

## Fallback: If twikit auth also fails

If cookies expire and credentials stop working:
1. User needs to manually refresh cookies (same as current approach)
2. Could add a helper script to generate cookies via browser login
3. The existing `DISCORD_WEBHOOK_URL` in `.env` is unused - could be used as an alternative delivery method
